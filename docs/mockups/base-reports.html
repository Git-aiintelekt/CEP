Copy on add, as chosen. A base pack is a set of datasets, reports and dashboards kept by the platform. A workspace adds a pack, picks its own Postal connection and databases, and gets its own copies: it may edit them, and later catalogue changes reach it only when it adds the pack again. The first pack is Email Campaign Reports, rebuilt from CmpReport: 2 datasets (one row per email, one row per campaign) + 3 new ones (link clicks, opens by device and client, bounce replies), 13 reports, 2 dashboards.

What gets built, in words

  • Packs ship with the release as files in the code (datasets as SQL with the Postal databases and the campaign-name table as blanks, reports and dashboards as the editor saves them), so each version is reviewed and tested; the back-office lists them, it does not edit them.
  • Adding a pack checks the connection has every table it reads, fills the blanks, test-runs each dataset, then creates the datasets, reports and dashboards through the same checks as by hand, in one go: all or nothing. The workspace records the pack and its version.
  • Email Campaign Reports, from CmpReport: the two datasets the Email 01–05 reports use today, plus Link Clicks (Postal's links and clicks), Opens (Postal's loads, sorted by device and client, machine opens flagged) and Bounces (the last reply text); 13 reports and the two dashboards from the assessment.
  • Not copied: CmpReport's sign-in, users, mail settings, health pages and its one renamed campaign.
  • Then CITY HT: its demo reports removed, the pack added on its Postal connection, each report run and checked.
Recommendation: Option 1. The packs are few and whole: a dialog beside New Report adds one in three steps and shows exactly what it will need and make. A gallery page earns its place once there are many packs and people want single reports; it can come later on the same catalogue.
