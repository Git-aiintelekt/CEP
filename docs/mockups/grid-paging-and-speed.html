Why the AI-built reports are slow

The AI is not the slow part: once a report is saved it runs like any report. Each run goes live to the Citi database (MySQL 8.0, Citi-TT-Analysis DB 8.0), and the SMS Receipt Messages dataset reads sms_mailer_master: 6.9 million rows, 3.4 GB. A 30-day report adds up about 1.1 million receipts on every run. Measured on .51 today, uncached:

Making them faster: what I would do

  • 1. Keep results longer for Report Databases. A result from a workspace's own database is kept for 15 minutes instead of 60 seconds (other data stays at 60 s). The run line says kept from 10:42, and Refresh runs it again now. Opening a report or a dashboard again then takes under a second. In CEP only, no change to the Citi database.
  • 2. Date filters that can use the index. The AI is told to filter dates on the dataset's time field (sent_at), never on a field computed from it, and the editor turns a "last N days" rule on a DATE(…) field of a query dataset into one on its time field when the dataset says which one. This brings 23 s down to about 19 s on today's data. A small gain alone, but it is what lets step 3 work.
  • 3. An index on the Citi side (their DBA, not CEP). CREATE INDEX idx_receipt_day ON sms_mailer_master (CAMPAIGN_NAME, DIRECTION, SENT_AT, STATUS, STORE_NUMBER, CARRIER_NAME, LINK_CLICKED) lets MySQL answer the totals from the index alone: expected 2 to 4 s instead of 20 to 33 s. Our login is read-only, so I would write it up for whoever runs that database.
  • Later, if live is still too slow: a kept copy. Insights could copy a dataset into its own reporting database on a schedule (hourly or nightly) and run the reports there in well under a second. That is a bigger piece of work, offered separately.
Recommendation: Option A for the pager, with steps 1 and 2 built now and step 3 sent to the Citi DBA. Option A shows where you are in a long list and lets you choose 50 or 100 rows; Option B is tidier but loses the page numbers. Steps 1 and 2 are in CEP's hands; step 3 gives the big gain, but only the database owner can add the index.
