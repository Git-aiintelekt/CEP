Input validation. Every limit comes from the table the field is saved to (type and length), published once by the API and read by the form. The form stops typing at the limit, the server rejects anything that slips past, and the user can always see how much room is left. Three ways to show it, each in the same four states: typing, near the limit (last 10%), at the limit, and a type error from the server.

Option 1 — counter at the end of the labelUses the slot the Field primitive already has. Always visible, grey until the last 10%, then amber, then red at the limit. The field border follows.

Where the rules come fromOne endpoint, generated from the Django models, cached by the browser for the session. The same rule drives the input's maxLength, the Zod schema, the counter, and the server's check.
