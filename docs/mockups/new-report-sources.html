New Report: connect a database and upload a file without leaving it, with ClickHouse as a third kind of database. Today New Report lists the built-in datasets, a workspace's mapped databases and its files; a database can only be connected in Engagement's Settings → Report Databases, by an administrator, and only MySQL or PostgreSQL. Three ways to put both on New Report follow, each in a busy workspace (two databases, two files) and an empty one (City HT today: none). The Connect a Database panel and the permissions are shared by all three. Recommendation at the end.

Option 1 · Two Tiles in the List
Connect a Database sits under Your Databases, as Upload a File sits under Your FilesNothing moves: the page keeps one list. Your Databases shows even when empty, so the tile always has a home. The tile opens the Connect a Database panel over the page; when it is done, the new database is chosen and the query window opens on it.

"Even user can upload a files": if you meant everyone who can open Insights, that is Choice B on the second row. Reporting on a file still needs the right to make a report (Report Edit), so B also means a viewer can make reports from their own files.

What gets built, in words

  • ClickHouse connections. Database patch 0071_report_connection_clickhouse.sql lets report_connection.engine be clickhouse (applied with your OK, on both databases). apps/insights/external.py reads ClickHouse over its HTTP interface with the existing client (apps/insights/clickhouse.py): every query runs with readonly = 1, the workspace's statement time limit and time zone. Test Connection reads the version, the tables and views, and the account's grants (SHOW GRANTS); an account with INSERT, ALTER, DROP, CREATE or TRUNCATE is refused. Map a Dataset, the query window and its guard, Write It for Me and reports, dashboards, schedules and exports work on it as on MySQL and PostgreSQL (the compiler already writes ClickHouse SQL).
  • Settings → Report Databases offers ClickHouse too (same form); its help chapter and the user guide say how to make a read-only account.
  • New Report gets the chosen layout, the Connect a Database panel (the existing endpoints POST /workspace/report-databases/test/, POST /workspace/report-databases/, …/sources/, …/datasets/) and, after Create Report, the editor on the new dataset; Write a Query opens /insights/reports/new/query/<id>.
  • Upload a File stays on New Report; with Choice B the permission on /insights/uploads/ widens to Report View, and the Uploaded Files menu item shows for them.
  • Tests: ClickHouse test, refusal, sources, mapping and a report run against a faked HTTP server (no network in tests); the panel's two steps and the permission cases in vitest.

Recommendation

  • Option 1, Two Tiles in the List. It adds one tile where people already look, beside the Upload a File tile they know, keeps New Report one screen with no extra click, and the panel keeps them on the page. Option 2 adds a click for every report to help only the first one; Option 3 hides the built-in data behind a tab.
  • Connecting: Choice A (administrators), because the connection carries the database's password for the whole workspace. Uploading: Choice B if you want every Insights user to bring their own file; otherwise A.
