What every report shares

  • Runs as the signed-in user under the workspace's isolation, read-only, with a 15-second limit per query. A preview stops at 500 rows; a full run pages 50 at a time.
  • Share with people or roles (View or Edit), Export as CSV or Excel, Schedule by email through the workspace's own mail server. Show the SQL is for report.admin only.
  • Permissions: report.view to open, report.edit to build and save, report.admin to see all reports and the SQL. Personal-data fields are masked without contact.pii.
  • Each dataset reads from one source: the main database (live), summary tables (refreshed by cep-jobs), a read replica (seconds behind) or an analytics store (for very large event data). Every report shows its freshness. A report never reads tables directly, so moving a dataset to another source is a back-office setting, not a rewrite.
  • Charts use the app's chart kit and its palette. Channel splits are neutral parts, so they take Blue, Teal and Periwinkle, never green or amber.

AI, through Claude or OpenAI

  • Both keys live in the back-office, encrypted. The browser never sees a key; every call goes from CEP's server to the provider.
  • The model returns a report definition through a schema-bound tool call (Claude tool use, OpenAI structured outputs). CEP checks it against the catalogue, retries once with the error, and only then shows the draft. The model never writes SQL and never sees another workspace.
  • Sent: the prompt, the catalogue of fields this person may use, and for Explain This Report the totals with personal data stripped. Not sent: customer rows, emails, phone numbers.
  • Each prompt, the chosen model, the draft and the token count are logged for 90 days. Prompts count against the plan's monthly number; a clarifying answer does not count.
  • Model names come from the back-office, so a newer model is a setting change, not a release.

The two editors compared

Option 1 · Field WellsBest for pivots and hierarchies: the layout of the result is visible in the wells. Familiar to anyone who has used a spreadsheet pivot. Needs width: three columns, so it is a desktop tool (tablet in a two-column mode, the wells as a drawer).
Option 2 · StepsBest for marketers asking a question: it reads as a sentence, and it shows an answer (the row count) from the start. Narrower, so it works on a tablet. Pivots are set in the Pivot view's own column picker, one step further away.

A change to the earlier tool list

The design system rules out chart libraries: every chart uses the app's chart kit (components/charts/). So ECharts drops out. The kit already draws bars, lines, area and the ranking list; the report builder adds pie and heatmap only if you want them, built into the kit the same way. The rest stands: TanStack Table for the grid, hierarchy and pivot; react-querybuilder for filters; dnd-kit for the wells; SQLGlot on the server to turn a report into SQL from the mapped datasets; XlsxWriter for Excel.

Recommendation

Option 1, Field Wells, because you asked for pivot and hierarchical views, and the wells are where those are built. Option 2's sparse start (an answer from the first second) can still be borrowed: a new report in Option 1 can show the row count until a field is placed.
