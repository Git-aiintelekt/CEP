Mockup, not the product. Static HTML on the app's colour and shape values. Insights → Reports: choosing the component a report belongs to when it is made (New Report, Ask for a Report) and changing it later. Sample names.

Today a report has no component of its own: it takes its dataset's, so every report on a Report Database or an uploaded file lands under Engagement. The change: a report keeps its own component, chosen when it is made, Automatic (the dataset's) by default, and changed by whoever may edit the report. The report list groups by it, and each component's Reports page (Engagement's Insights item, for example) lists the reports filed under it. The two options differ in where the choice sits.

Option A: a Component field wherever a report is made, and beside Folder on the report

One select, the same everywhere: in New Report under the name, in Ask for a Report beside the model, on the report page beside Folder, and in the editor's header.

What gets built, in words

  • The report's own component: patch 0075 adds report.component_key (empty = Automatic, the dataset's component). The list, its component chips, each component's Reports page and the dataset filter use it.
  • Which components: Automatic, then the components on the workspace's plan (Engagement, Insights, and others as they are added). Ask for a Report and New Report remember nothing: each report starts on Automatic unless you choose.
  • Where it is chosen: New Report, Build a Report from a Query, and Ask for a Report (the draft keeps it; Open in Editor files the report there).
  • Who changes it: anyone who may edit the report; on the report page it is saved at once, in the editor with Save; the list moves the report to its new group.
  • Help and tests: "File a report under a component" in the Insights help; tests for the default, each place it is chosen, the change, and the list's grouping.
Recommendation: Option A. You asked for the choice when creating and editing; a visible Component field in each form and beside Folder on the report makes it obvious and one click to change. Option B keeps the headers quieter but hides the choice behind a link.
