Mockup, not the product. Static HTML on the app's colour and shape values. Settings → Report Databases → Map a Dataset, and the connection dialog. Sample names: a MySQL 5.7 database of 1,284 tables and views, 250 GB.

Browsing a customer database reads its catalogue (names and column types), never its data, and C360 stores none of it. The names come live from the database with one statement that opens no table (SHOW FULL TABLES, milliseconds even for 1,284 names); searching is done on that answer, held in memory for 10 minutes so typing does not ask the database again for every letter, then dropped. A table's columns are read live when someone opens it, that table only. The two options differ in how you find a table.

Choosing the database

In the connection dialog, after the account: Find Databases lists the databases the account can see, and you pick one instead of typing its name. A list of names only; no data is read.

What gets built, in words

  • Find Databases in the connection dialog: SHOW DATABASES (MySQL) or the schemas the account can use (PostgreSQL), names and table counts only; the Database field becomes a picker. Typing a name still works.
  • Nothing about the customer's database is stored. The names come live from one SHOW FULL TABLES (it opens no table), held in the cache 10 minutes for the search and then dropped; Reload the List reads them again. A table's columns and row estimate are read live when it is chosen, from the catalogue for that one table.
  • Search and groups worked out by C360 on those names: the search filters all of them, the first 50 matches come back, more on request; groups are name prefixes with 5 or more tables (others under Other), views have their own group; under 50 tables, one plain list.
  • Pins per database, shared by the workspace's administrators and report builders: the only thing kept, the pinned tables' names.
  • The join check on the first 10,000 rows of the base table, with the share that matches and whether the join repeats rows; it never counts a whole table.
  • The sample rows stay 5 rows with no sorting, read only when asked for.
  • A patch for the pins (a list of names on the connection); tests for the search, the groups, the on-demand columns, the 10-minute memory and the sampled join check; help in the Report Databases chapter.
Recommendation: Option A. With 1,284 tables people mostly know part of a name, so search first is the fastest route, and pins keep the few tables they use one click away. The folded groups still give the shape of the database when nothing is typed. Option B suits browsing a database you don't know, at the cost of a second column and more clicks per table.
