Save feedback — mockup, not the product. One rule for the whole app: every save says that it worked or why it did not, in a sentence that names the thing, and never shows a database's or a browser's own words. Toasts, banners and fields are the components CEP already has (Toast, Notice, Field); only the wording and where they are used change. Two real choices are shown as options: how an instant switch confirms (A or B) and whether a server error shows a reference code (1 or 2).

What gets built, in words

In the browser

  • One helper, saveFailure(error, "the sender"), turns any failed save into a title, a sentence, a tone and (option 1) a reference: field errors, a general problem, conflict (409, the server's own sentence, as today), no permission (403), signed out (401), database not answering (503), CEP's problem (500), no connection. Every form, toast and banner uses it; “Invalid input”, “Internal Server Error”, “Request failed” and the browser's “Failed to fetch” never reach the screen.
  • Success: a toast for the 51 saves that show nothing today (dialogs that close, deletes, archives, Settings saves); the chosen option (A or B) for the instant switches.
  • The 6 silent failures get their message (rotate webhook, Mailgun Inspect check and remove, turning off two-step sign-in, ending a support session, the campaign's tested mark). Problems not about a shown field appear in the banner. Four errors drawn as grey status lines become error banners. The Mail Server test's wrong title and the two “we” / “our side” sentences are reworded.
  • Signed out: the login page shows “Your session ended”.

On the server

  • Every error answers in the same JSON shape (problem+json), never Django's HTML page or a traceback, and never database wording.
  • A duplicate (unique violation) becomes 400 on its field: “… already exists”. A broken database rule (check violation) becomes 400 with a plain sentence for the rules CEP has (e.g. re-entry days, governance limits). Row-level security becomes 403. Database not answering becomes 503. Anything else becomes 500 with the time and a reference that matches its entry on the back-office Errors page.
  • A 400's title becomes “Check the highlighted fields” instead of “Invalid input”.

Written down and tested

  • A “Save feedback” section in docs: which component when (toast, the field, the banner, the tick), and the sentences.
  • Tests: the helper for every case, the server's handler for each database error, and the silent ones now speaking.

Recommendation

Option A for instant settings: a toast on every switch gets noisy, and the tick sits where the eye already is. Option 1 for server errors: the reference costs one short code and lets support find the cause on the Errors page in seconds.
